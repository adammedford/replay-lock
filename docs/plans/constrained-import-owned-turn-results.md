# #127: operation-boundary owned fixture turns

Status: **partial retained prototype**, outside main. On2026-10-03 the user
accepted that a call already admitted against an immutable qualified snapshot may
finish after a mid-call file edit. Detected drift makes that generation terminal
before another owner-mediated turn. Effect permissions, artifact/provenance rules,
runtime pins and the60000ms test ceilings are unchanged. This is not complete G1B
feasibility, production delivery or new application eligibility.

## Implemented slice

`scripts/prototype-import-generation.mjs` owns a private source map and one active
fixture turn. Whole-closure qualification reuses the existing bounded placement
grammar. Source and fixed HTML/config/package/lockfile inputs are read through
bounded descriptors, with UTF-8 roundtrip, realpath, file-identity and before/after
stat checks. Currentness is checked at admission and completion; detected drift
closes irreversibly. Restoring original text does not reopen the generation.
Stable observed reads are **not** an atomic arbitrary-filesystem snapshot proof.

Loads return retained authored strings instead of reading mutable application
source again. A reserved turn prevents concurrent admission; completion checks
cannot overlap or clear a newer turn. The live Node handler imports and invokes
inside this owner. The fixed trusted browser button uses a private admission/
completion bridge; an admitted turn may load the old snapshot even after detected
source changes, but another button click must request fresh admission and refuse.
Application delivery outside a live turn is refused at the fixture HTTP seam.
This bridge is experiment plumbing, not an exported package loader interface.

Fixed generated Vite configuration and the normal isolated verifier's generated
test harness are trusted infrastructure, not application/package exceptions.
The harness classification is restricted to test mode and its generated scratch
path pattern. No arbitrary configuration/plugin support is claimed.

The legacy `startImportWorkflow()` default keeps the original load-only gate and
its original UI semantics. `ownedTurns:true` is only a scripts-level fixture
selector. The earlier failed-cache characterizations remain unchanged and still
demonstrate why a load hook alone is insufficient. No `src/`, dependency, lockfile,
public export or accepted-artifact format is changed.

  refuses409 GENERATION_CLOSED. Restoring3 still refuses. Its actual complete
  candidate is inspected before explicit CLI review; normal isolated verify passes
  against restored current source in a fresh verifier generation.
- An ordinary owned browser positive observes7, yields a complete inspected
  candidate, is explicitly reviewed and passes normal Browser Mode verification.
- The browser timing probe waits for actual server admission, replaces the helper
  with primitive4 plus an unused object initializer, then releases the response
  before entry loading. Original admitted bytes naturally return7. Completion
  detects drift; another click and a fresh page on that host report
  GENERATION_CLOSED. A premature direct entry HTTP request is refused.
- An empty completion request is refused with409 TURN_INVALID before an ordinary
  positive turn. An aborted browser completion request produces HOST_FAILURE and
  still settles the UI; that abandoned turn is not reused or reviewed.

The unsupported replacement contains no native effect. No expected observation
or artifact is manufactured. **No observation from the mid-turn drift probe is
reviewed or accepted**: current analyzer/capture metadata is not yet bound to this
owned snapshot. Letting the turn finish does not by itself authorize recording it
under V2 provenance. Original fixtures are removed by existing owned cleanup.

The Node refusal test went red on the legacy200 response before implementation.
Browser timing went red because the old button did not request admission. A
generated-verifier-harness classification gap was caught by the real CLI check
and corrected without bypassing review or replacing the isolated verifier.

Independent Standards and Spec reviewers identified that idle completion with an
absent token could clear a newer turn; Standards also found that a rejected
completion fetch could leave the UI unsettled. Both public-workflow regression
checks failed before the fixes. Completion now requires an active matching string
token, and completion transport errors settle the trusted UI independently.
Both reviewers confirmed the findings resolved, with no remaining actionable
findings in this slice. Their review does not certify complete G1B feasibility.

## Remaining proof obligations

This owner binds **authored** bytes, not final Vite/Vitest/browser evaluated bytes.
Trusted recording transforms still run normally. It does not establish coherent
snapshot capture across unmanaged writes, complete resolver/alias/condition/adapter
identity, native/external/builtin/data/virtual/extra-entry bypass coverage, revoked
escaped namespaces, warm isolated-worker fencing or complete fresh-process/server/
browser lifecycle ownership. Trusted-controller turns are not all browser execution.

Metadata drift classification, exact-boundary resources, concurrent/abandoned-turn
cleanup and operation linearization need further adversarial coverage. Mid-turn
observation currentness is a separate gate, not a silently added artifact fact.
Safe equivalent edits can be verified in a fresh verifier generation; live source
rewrites conservatively close the old generation. The complete matrix, lost
admissions, extended dogfood/conformance/performance and source-only pinned-app
comparison remain outstanding. G1B stays unmet; #106 open and #107 blocked.
