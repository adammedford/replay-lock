# #127: approved evaluator-delegate witness

The user approved the proposed fixture-only ordinary-HTTP diagnostic signal on
2026-10-11. This retained slice installs that signal and characterizes the existing
lazy guard. It does not install the proposed staged release barrier.

`evaluatorWitness:true` is a private fixed-fixture option requiring the existing
final Node adapter and its sealed/native configuration. Immediately after the
existing late control and comparison, but immediately before delegating to the
preserved original inline or external evaluator, trusted host dispatch throws
`SYNTHETIC_EVALUATOR_DELEGATE_REACHED`. The ordinary `/invoke` request exposes this
distinct marker only when the option is enabled. Witness-off error handling and
execution are unchanged. No application throw/counter, authored qualifier
exception, effect permission, production taxonomy or persisted artifact is added.

The separate witness experiment uses the same fixed source and normal HTTP
invocation. All witness observations remain empty and none are reviewed:

| Existing final Node mode | Witness HTTP outcome |
| --- | --- |
| Unchanged release | 409 / delegate-reached marker |
| Original late helper mutation, comparison disabled | 409 / delegate-reached marker |
| Original late helper mutation, comparison enabled | 409 / delegate-reached marker |
| Mutated fetched preparation reply copy | 409 / `EVALUATED_INPUT_REFUSED` |

The third row is a **failed whole-family release property**, not prevention: entry
has reached the delegation point before the helper's late comparison can run.
The marker stops entry before the original evaluator is called, so it measures
dispatch reachability, not actual original evaluator execution. It is not a native
effect oracle and does not establish observer/transitive executable qualification.
The first reached delegate in these controls is entry; external witness placement
is source-reviewed, not independently exercised by these entry-stopping controls.
The fourth row checks that earlier refusal is distinguishable from the marker;
it still mutates a fetched reply copy, not the Vite cache.
