## Decision and handoff

**Best narrow Epic target:** `getUserImgSrc` on the existing search → profile → notes workflow. The value shape is simple, the source has explicit call sites in each visited page, and its static blockers trace to unrelated imports/module initialization. First run a read-only diagnostic of the four codes at this locator, then propose a scoped analyzer/replay-export change that qualifies this exact helper while preserving module-initialization safety. This is a hypothesis, not a claim that existing configuration suffices. A second candidate is `parsePermissionString`, but its calls are not established by the four-page workload.

**Acceptance checks for a follow-up implementation:** With the same pinned source, unchanged business code and dependencies, show `getUserImgSrc` eligible in the relevant realm; record at least one actual invocation with synthetic input and a portable output; retain a candidate; review explicitly; replay offline; survive a behavior-preserving edit; fail on a targeted URL/fallback regression; and report no privacy or recording blocks for the target. Keep Node/browser invocation counts distinct and keep the existing `createTimer` block attributed rather than treating it as candidate omission. Demonstrate that the analyzer still rejects a module with genuinely effectful initialization. The runner must also verify owned process cleanup before claiming an unattended journey.

**Current limitation:** There is no demonstrated useful supported Epic candidate. The two eligible callables concern timing/reporter machinery, not search/profile/notes behavior, and their function-valued results block or likely block portability. The #65 existing-application characterization journey remains **unmet**. If the helper-isolation analysis cannot safely enable a useful Epic target, ticket #68's next decision gate should assess and pin another existing application. The already pinned Homer cache is a poor immediate substitute for the same goal because its core Vue single-file components sit outside the present JavaScript/TypeScript callable boundary (`docs/pilots/results.md`). This exploration does not claim that a replacement application has been selected or pinned.
